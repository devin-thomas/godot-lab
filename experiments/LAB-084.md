### Fixture, reset and unavailable path

Scenario: `network-chaos`. Fixture: Original operation stream and deterministic fault-seed recipe.

Reset ownership: Remove proxy/fault injection and release process/port resources.

Limits and unavailable route: Fault adapter is proposed lab tooling; actual wire loss is distinct from synthetic event replay.

Use original bounded fixtures with hash/license/seed manifests. Readiness must name the actual missing adapter and a useful labeled fallback if possible. Fixture replay does not establish device/provider support.

### Positive acceptance

- Fault trace matches selected seed
- Reliable semantic operations do not duplicate
- Timeout becomes explicit failure
- After recovery replicas converge

### Failure and negative controls

- Impossible/unbounded delay profile rejects
- Proxy exit reports broken transport

Additionally exercise reset/exit during the longest operation, repeated entry and fixture isolation. Observe real mechanisms; never assign the expected final result to make the assertion pass.
