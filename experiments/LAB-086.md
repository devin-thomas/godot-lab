### Interaction

1. Probe backend availability
2. Exchange local signaling fixtures
3. Send a typed bounded message
4. Disconnect/reconnect and inspect state

### Fixture, reset and unavailable path

Scenario: `webrtc-bridge`. Fixture: Original two-browser message room and approved local signaling service.

Reset ownership: Close channels/peers and discard signaling/session fixtures.

Limits and unavailable route: Native plugin/browser requirements are probes. No public NAT/STUN service assumption.

Use original bounded fixtures with hash/license/seed manifests. Readiness must name the actual missing adapter and a useful labeled fallback if possible. Fixture replay does not establish device/provider support.

### Positive acceptance

- Both peers establish actual channel
- Message order follows declared channel policy
- Disconnect reported
- Unsupported backend retains labeled fixture path

### Failure and negative controls

- Malformed signaling rejects
- Connection timeout is not promoted to success

Additionally exercise reset/exit during the longest operation, repeated entry and fixture isolation. Observe real mechanisms; never assign the expected final result to make the assertion pass.
