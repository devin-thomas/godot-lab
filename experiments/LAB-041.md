### Interaction

1. Connect an original lever to a gate
2. Trigger multiple sources
3. Inspect ordered receipts
4. Disconnect a receiver and reset

### Fixture, reset and unavailable path

Scenario: `signal-switchboard`. Fixture: Original lever, lamp and gate nodes with stable names.

Reset ownership: Disconnect owned routes and restore initial states.

Limits and unavailable route: Ordering policy belongs to this lab; not a universal global event bus.

Use original bounded fixtures with hash/license/seed manifests. Readiness must name the actual missing adapter and a useful labeled fallback if possible. Fixture replay does not establish device/provider support.

### Positive acceptance

- One emit invokes one registered receiver
- Duplicate connect does not multiply effects
- Freed receiver is removed safely
- Event trace order matches declared ordering

### Failure and negative controls

- Invalid payload rejects
- Missing receiver reports unavailable route

Additionally exercise reset/exit during the longest operation, repeated entry and fixture isolation. Observe real mechanisms; never assign the expected final result to make the assertion pass.
