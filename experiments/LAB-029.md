### Interaction

1. Enter neighboring chunk
2. Inspect loading/activation state
3. Change one owned object
4. Unload and revisit

### Fixture, reset and unavailable path

Scenario: `streaming-depot`. Fixture: Original 3 x 3 chunk map with stable object IDs.

Reset ownership: Cancel pending loads, free mounted chunks and restore fixture ledger.

Limits and unavailable route: Threaded load is not free scene-tree mutation; actual resource path is probed.

Use original bounded fixtures with hash/license/seed manifests. Readiness must name the actual missing adapter and a useful labeled fallback if possible. Fixture replay does not establish device/provider support.

### Positive acceptance

- Boundary activates requested chunk
- Changed object returns with correct state
- Cancelled load never mounts late
- Resident chunk cap holds

### Failure and negative controls

- Missing chunk displays error barrier
- Corrupt resource preserves current playable chunk

Additionally exercise reset/exit during the longest operation, repeated entry and fixture isolation. Observe real mechanisms; never assign the expected final result to make the assertion pass.
