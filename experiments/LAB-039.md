### Interaction

1. Browse original fixture variants
2. Inspect rights/hash/size
3. Stage a selected fixture
4. Commit or cancel and replay

### Fixture, reset and unavailable path

Scenario: `fixture-pantry`. Fixture: Original small geometry, texture, tone and malformed test fixtures.

Reset ownership: Remove staged proposals and restore selected baseline fixture.

Limits and unavailable route: Only approved original/licensed inputs; no automatic arbitrary-path import.

Use original bounded fixtures with hash/license/seed manifests. Readiness must name the actual missing adapter and a useful labeled fallback if possible. Fixture replay does not establish device/provider support.

### Positive acceptance

- Hashes identify exact fixture
- Size limits checked before adoption
- Cancel leaves current scene unchanged
- Commit preserves source identity in receipt

### Failure and negative controls

- Oversized fixture refuses staging
- Unapproved external path is rejected

Additionally exercise reset/exit during the longest operation, repeated entry and fixture isolation. Observe real mechanisms; never assign the expected final result to make the assertion pass.
