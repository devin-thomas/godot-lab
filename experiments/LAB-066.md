### Interaction

1. Activate original monitor
2. Move source camera
3. Interact with displayed panel
4. Limit recursive view and reset

### Fixture, reset and unavailable path

Scenario: `viewport-mirrors`. Fixture: Original room monitor and bounded two-view portal fixture.

Reset ownership: Release child viewports and restore source camera/input focus.

Limits and unavailable route: Portal illusion scope is explicit; no unlimited recursion or arbitrary cross-app capture.

Use original bounded fixtures with hash/license/seed manifests. Readiness must name the actual missing adapter and a useful labeled fallback if possible. Fixture replay does not establish device/provider support.

### Positive acceptance

- Displayed texture updates from intended camera
- Forwarded input affects correct panel
- Recursion cap holds
- Exit frees viewport resources

### Failure and negative controls

- Invalid source rejects
- Input outside panel cannot activate hidden control

Additionally exercise reset/exit during the longest operation, repeated entry and fixture isolation. Observe real mechanisms; never assign the expected final result to make the assertion pass.
