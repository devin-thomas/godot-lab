### Fixture, reset and unavailable path

Scenario: `prediction-track`. Fixture: Original constrained movement track with ticked input and snapshot records.

Reset ownership: Stop peers, clear pending inputs and restore authoritative baseline.

Limits and unavailable route: Networked physics determinism not assumed; no competitive-game guarantee.

Use original bounded fixtures with hash/license/seed manifests. Readiness must name the actual missing adapter and a useful labeled fallback if possible. Fixture replay does not establish device/provider support.

### Positive acceptance

- Acknowledged inputs removed exactly once
- Reconciliation converges within declared tolerance
- Stale snapshots ignored visibly
- Server remains authority

### Failure and negative controls

- Duplicate/out-of-order snapshot handled by policy
- Unknown actor snapshot refuses apply

Additionally exercise reset/exit during the longest operation, repeated entry and fixture isolation. Observe real mechanisms; never assign the expected final result to make the assertion pass.
