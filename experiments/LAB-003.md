# LAB-003: Pathfinder garden

Scenario: `navigation`. State: automated-verified on the recorded Windows build; human/device gates deferred. See BUILD_STATUS for evidence.

Dispatch a courier to the fixed gold destination pad and watch it follow an authored navigation mesh around a solid tower. A visible obstacle makes the path meaningful; a straight interpolation through the obstacle would not demonstrate navigation.

## Play and reset

The operation starts the real agent at the mint-side origin and sets its target to the gold pad. Display the current path/arrival state while the agent moves. Reset returns the agent to the baseline. Exit cancels following and frees the lab's navigation resources.

## Acceptance

Wait for the navigation map to synchronize, request the fixed destination, follow the real navigation path, and arrive within a defined tolerance/time limit. Inspect the non-straight path around the tower. Test reset and dispatch again. Destination selection and multiple targets are future extensions.

State/path assertions establish navigation outcomes. Rendered evidence verifies the path and obstruction are readable. A future crowd-avoidance lab requires its own multi-agent evidence.

Reference: [NavigationAgent3D](https://docs.godotengine.org/en/stable/classes/class_navigationagent3d.html).
