### Fixture, reset and unavailable path

Scenario: `xr-hands`. Fixture: Original joint-pose recording and reach/pinch calibration objects.

Reset ownership: Release grabbed objects and restore origin/tracking-source state.

Limits and unavailable route: Hand tracking extensions and API signatures need probes; no hardware qualification from fixture replay.

Use original bounded fixtures with hash/license/seed manifests. Readiness must name the actual missing adapter and a useful labeled fallback if possible. Fixture replay does not establish device/provider support.

### Positive acceptance

- Fixture/live provenance remains visible
- Pinch transition emits once
- Tracking loss follows safe declared policy
- Joint visualization matches recorded fixture

### Failure and negative controls

- Unsupported extension leaves fixture path usable
- Invalid joint array refuses pose

Additionally exercise reset/exit during the longest operation, repeated entry and fixture isolation. Observe real mechanisms; never assign the expected final result to make the assertion pass.
