# Delivery milestones

The previous six-lab release becomes M0. The full program is specified; future wave labels do not imply implementation. Counts and laboratory memberships are derived in [CAPABILITY_MATRIX](CAPABILITY_MATRIX.md).

| Wave | Deliverable | Exit criteria |
|---|---|---|
| M0 Bootstrap | Existing six-room executable, bounded replay/Cappy and public-source proof | Historical recorded gates remain traceable; do not upgrade them to new-depth proof |
| M1 Shared playable platform | Module lifecycle, typed operations/receipts, profiles/fixtures/reset, inspector, first broader core route | Equivalent UI/scenario operations, failure/reset cycles, source-bound evidence and clean export; one composed journey |
| M2 Game systems and expressive art | Character/animation/combat, world, narrative, sound and deliberate original art | Cross-lab gameplay journey, timed event/audio/animation proof and extraction scenes; depth tests for relevant baseline labs |
| M3 Production and connected systems | Live API/CLI/MCP, one-run Cappy coexistence, network sessions, scripted assets/editor, records/jobs | Agent-controlled live capture, real multi-process failures/recovery, recipe/import round trips, cancellation and coherent production journey |
| M4 Advanced systems qualification | Rendering/performance/native/interchange investigations and regression matrices | Named toolchain/renderer profiles, measurable budgets, deliberate negative controls and independently reusable results |
| M5 Optional devices and targets | Browser/mobile/multi-device/XR adapters | Actual available target builds/automated routes; honest device/human limits and meaningful fallback; core remains independent |

## Order and admission

[ROADMAP](ROADMAP.md) is the dependency graph and topological implementation order. Every lab has A implementation and B qualification tasks; the first six receive separate depth tasks. Earlier wave assignment never waives a prerequisite. Dependent journeys require qualified component behavior, not merely an implementation checkbox.

Start CORE-002..CORE-007 and CORE-017 before broad room construction. Develop representative vertical slices against these boundaries, then reuse components. Live transport/capture jobs and authoring/native adapters follow their system gates. Renderer/hardware spikes can run independently when source ownership and worker reservations are explicit.

Each wave preserves a useful default executable, original bounded fixtures, truthful unavailable UI, automatic failure/reset coverage, extraction evidence, publishable source and profile-specific exports. Full human/device gates stay pending when unavailable; automation continues.

## Depth acceptance

A parameter inspector alone is not depth. A system must respond to meaningful variants and adverse cases, expose why the behavior changes, and participate in a journey. Comparison presets and actual temporal recordings qualify animation/effects; real decoded channels qualify sound; real peers qualify transport; staged hostile fixtures qualify import/recovery. The artifact must remain physically playable even if every proof is automated.
