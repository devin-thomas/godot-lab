# Capability profiles and readiness

Profiles are planned selection/qualification boundaries. Current proof is Windows + Compatibility + six bounded bootstrap routes.

| Profile | Purpose | Automated qualification | Unavailable path |
|---|---|---|---|
| CoreLocal | Playable world, input, documents, low-cost visuals/sound | Headless, rendered desktop, clean source/export | Missing mandatory fixture is visible build failure |
| RenderAdvanced | Lighting, compute, post-processing and renderer studies | Actual GPU/renderer probe, pixels, timing and limits | Lower-cost material/CPU result labeled by mechanism |
| NetworkLocal | Sessions, authority and transport | Real loopback peers, loss/delay/reconnect/incompatible messages | Offline fixture peers labeled simulation |
| ProductionTools | Cappy, OBS, FFmpeg, authoring and workers | Discovery, game pixels, encoded sound, manifests, cancellation | Ordinary play remains available; capture names missing provider |
| EditorNative | Editor plugins, resources, C#/GDExtension | Compile/load, editor process, extraction and ABI probes | Useful runtime equivalent; native adapter unverified |
| Web | Browser/export constraints and bridges | Actual browser export, input/media/readiness | Desktop domain fixture only |
| Mobile | Touch, sensors, lifecycle and exports | SDK compile, simulator/emulator and available host tests | Simulated samples do not qualify touch/sensors/thermals |
| XR | Spatial views, controller/hand inputs | OpenXR/plugin/runtime and available simulator tests | Desktop spatial fixture; hardware comfort pending |

Probe engine/build flavor, export platform, renderer/backend, extensions/tools, assets, providers, permissions and actual runtime. Do not infer readiness from a machine name or menu toggle. Report which route supplied evidence. Optional SDKs, providers and native builds cannot become hidden prerequisites for default startup.
